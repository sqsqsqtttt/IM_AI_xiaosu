# AI_USAGE.md — 我如何使用 AI 完成这个项目

## 1. 你用了哪些 AI 工具（Claude Code / Cursor / Codex / 其他）？分别用在哪些环节？

我用的是前几天deepseek官方刚刚发布的deepseek　harness预览版（主要进行干活的agent，缓存命中率可达到100%，推荐面试官也可以尝试一下，强烈推荐），然后平时用的是Claude code，codex，trae等，不过本项目并没有使用这些工具，主要就是用的harness，同时也用到了一些网页端的AI产品，比如豆包，deep seek网页端，他们主要是用来回答我的一些疑问，验证一些我的猜想，提供一些思路，还有就是解答一些基础知识，这些任务他们都能很好的胜任，我还用到了deep seekAPI，在项目配置文件中填写的就是deep seek开放平台的APIKEY，用的是较为便宜的V4flash模型，并且关闭了思考模式。这些工具使用的过程中，方案设计环节我是同时问了网页端的多个产品，也问了harness，开启了计划模式，他会给我一个计划说明书，给我生成一个待办，哪里我认为不合适或者有疑问我会多问几遍或者进行修改，当我仔细核查，确认方案可行之后才会命令harness进行编码，同时我会将项目拆解成多个具有里程碑式的环节，我不会让harness直接把所有事情干完，而是一步一步来进行，每次进行完一个里程碑事件我会在当前工作区新开一个会话，这样既能减少堆积太多窗口内容导致模型回答不精准，也能降低token消耗防止token指数级增长，然后公司文档等内容由免费的网页端模型豆包等生成，然后就是编写测试用例由harness负责编写，我负责审核以及补充，还有排查故障环节，我会自己先分析查看大致是什么问题，可能是哪里出错了，尽量自己先弄懂，然后再让harness修改，因为毕竟自己懂得越多，AI编写的代码才更加可控，更加符合自己的想法，才能更准确。


## 2. 一个具体例子：我给的 prompt、AI 生成的代码、哪里能用、哪里必须改、为什么


开头提示词：阅读文件夹里的html文件，我需要按照里面的要求做一个项目，我使用钉钉平台来接入机器人，你先看一下进行分析以及规划，选出最优方案，进行可行性分析，后面如果需要我做什么你需要告诉我，比如注册钉钉创建机器人应用这些，你先做一个规划我看一下方案是否可行

在这里AI生成的代码框架是可以用的，但是最终的APIKEY需要我自己来填写，这个是隐私配置，必须慎重，尽量自己来完善



## 3. 有没有一次 AI 把我带沟里去的经历？怎么发现、怎么收拾？

有，而且不止一次。最典型的是钉钉机器人"收不到消息"：
AI 按 Node SDK 的 README 用 `registerAllEventListener`（EVENT 通道）接机器人消息，长连接也连上了，但用户发消息就是收不到。查日志发现网关只发心跳 ping，没有任何消息事件，harness一开始怀疑是我后台没发布、没选 Stream 模式，我也仔细和harness来回确认好几轮；
收拾方式：在 SDK 里给所有下行消息加了观测日志，并对照官方 Python SDK 的示例发现机器人消息是通过 `register_callback_handler` 注册的——机器人消息走的是 CALLBACK 通道（type=CALLBACK），不是 EVENT。补上 `registerCallbackListener('/v1.0/im/bot/messages/get', ...)` 后消息立刻通了。
教训：同一平台不同语言的 SDK 文档可能暗示不同的接入方式，排障时先抓原始下行报文（什么 type、什么 topic），再对照多语言示例交叉验证**，不能只信一个 README。

我还记得很有意思的一次，有一次harness自己把自己杀死了，因为deepseek harness是依赖node.js环境跑在3080端口的，但是因为某次故障排查要把node的相关进程关闭，导致harness把3080端口给关闭了，我刚开始没觉得有什么问题，直到我发现任务处理已经快要四十分钟了还停在这里一直思考，我才反应出来不对劲，我当时想要暂停该任务暂停不了，我就问了一下网页端的AI工具这是怎么回事，通过分析我就立马知道了在处理任务的过程中harness自己把自己杀死了，果断重启harness，任务就恢复了正常。



## 4. 你怎么验证 AI 生成的代码是对的？


我认为有一个思路就是每次AI生成完代码之后，我会让AI再写一个commit massage，每次我都会仔细阅读一下，看看AI到底修改了什么，做了什么，我会仔细查看逻辑是否正确，还有就是我使用了一个skills叫做guard skills,这个skills会在AI写完之后自动的再过一遍质检，这个帮我省了很多事情，我认为能多加一层质检就尽量加一层保险，还有就是每次harness做完一个里程碑的功能，我都会将代码备份一份，防止后面AI乱改破坏了现有正确的代码，并且写完的代码我都会故意进行一些适当的“破坏”，我这个人其实就是喜欢多试试一些其它方案，我会在可控的范围内，看一下这种方案到底会发生什么，具体原理是什么，很喜欢把事情弄清楚，这样子能帮我更深刻的知道为什么这么做，为什么不这么做，我认为AI编程重要的就是保持自己的判断力，而我就是那种不轻易相信别人，总是喜欢自我验证的人。




## 5. 如果让你再做一遍，你会怎么调整 AI 的使用方式？


我这次并没有把任务给分好，一个项目拆分的不够精准，最让我感受的一点就是在做项目的过程中我在一个对话窗口问了太多话了，后面发现token消耗的太快了，给我吓了一跳，心疼我的钱包，然后在做完一个完整的功能之后才开一个新的窗口，真的好费钱，下次我会在做项目之前规划好窗口的任务，每个窗口做一个具体的任务，会让AI干活又快又准确
