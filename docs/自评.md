# 自评

## 我做的是什么，解决谁的什么问题

我做的是一个公司内部的AI助手“小苏”，员工可以在钉钉@小苏，然后小苏会基于企业内部的知识库回答员工的问题（带引用，知识库原话，附带位置），并且小苏会自动决策是否调用工具查数据，管理员可以在web后台维护知识库（支持.txt,.pdf,.docx,.md），查看对话日志（谁问了什么、调了什么工具、花了多少 token 以及多少钱）

解决的是：员工不清楚制度问题反复问领导，我做的系统可以减轻管理负担，系统汇总的数据可以用来统计员工对什么问题敏感，可以有针对的加强宣传该知识点，增强组织纪律性和凝聚性，可以将公司制度、手册等文件进行整理在一起，我认为可以方便上下级员工的检索负担。

## 我最得意的 1 个技术决策 + 1 个被迫的妥协

**得意：**

我认为我最得意的一个技术决策是我选择了 TypeScript作为该项目的开发语言，我一般在做一个项目之前都会先进行技术栈选型，而不是直接让AI开始动手做项目，因为我觉得这个是一个很重要的事情，如果选的语言，框架，数据库等技术栈不合适，会造成后续工作的很多困难，反而前置工作做足之后，权衡利弊选择了最符合当前项目的技术之后，再开始AI编程会更加顺利，这也是可行性分析，需求分析，技术栈选型我认为重要的原因，我会事先预想很多种方案，并让AI工具分析多种方案之间的利弊，再经过人（我自己）的综合考量敲定最终方案。在这里我选择TS语言的原因如下：
1. TS语言属于node.js生态，钉钉/飞书等官方SDK都是node.js生态最成熟（我自己电脑也是安装了node环境，并且我的微信小程序后端也是基于node开发的，我具有一定的经验）
2. AI生态，流式输出，工具调用在TS里面几行代码就能实现，兼容性好，方便
3. TS是一种全栈语言，，前后端都可以使用，我认为这可以方便我进行代码管理，更好维护
4. 我认为相比于python，虽然TS并没有python那么容易上手（我python和C++拿过蓝桥杯省奖），但TS在编译期查错更方便，大型项目较为可控，而对于Java，我认为java语言较为繁琐，　更适合大型企业项目（我的简历中论文项目用的java），但在该项目又不如TS方便，因此选择TS

**妥协：**

我在钉钉客户端并没有实现点击文档链接跳转的功能，不过实现在了web管理员端的对话测试里面，我认为想要实现链接跳转，需要将服务器部署出来，暴露在公网中，提供一个浏览文档的网站，我暂时并不想折腾云服务器和域名备案，因此并没有实现该功能，但如果后续有时间，我会尝试部署，把这个功能完善出来
